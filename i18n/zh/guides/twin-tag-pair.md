# 当一卷线轴的两枚芯片被读成两卷线轴

你在线轴的两个面各贴了一枚芯片，而你的库存现在显示的是**两**个条目，而不是一个。每枚芯片都能工作；各自打开各自的线轴。你在其中一个上修正的重量，永远不会出现在另一个上。

没有任何东西坏了。这两枚芯片几乎可以肯定从来就不是一对。

## 能一锤定音的测试

两枚芯片之所以是一对，是因为它们携带**相同的 Twin Tag ID**——这是写入时生成的值，只有在同一次写入会话中写入的芯片才共享它。读取两枚芯片并比较这个值：这就是全部的诊断。Tiger Studio 会显示它；任何能解码负载的读卡器也会。

完整的规则——包括还有哪些内容必须匹配，以及为什么仅凭时间戳不能作为证明——见
[TigerTag 芯片](../concepts/tigertag-chip.md)。

## 值不同：它们从来就不是一对

这是最常见的原因，而且只有一个来源：**这两枚芯片是分两次写入的**。第二次写入可能晚一秒，也可能晚一天，因此它会印上不同的 Twin Tag ID，从那一刻起，没有任何东西把这两枚芯片绑在一起。下游的每个工具把它们算作两卷线轴都是对的。

除了重写，没有别的修复办法。成对是在写入时形成的，否则就不成对。

## 把它们重写为一对

擦除两枚芯片，然后在同一次会话中一起写入：

| | 一对芯片如何写入 | 最适合 |
|---|---|---|
| **手机** — [Tiger NFC Connect](../products/tiger-nfc-connect.md) | *Dual NFC*：填一张表单，然后在同一次会话中写入第 1/2 枚和第 2/2 枚芯片 | 一卷线轴，无需硬件 |
| **桌面，两台读卡器** — [TigerPOD](../products/tigerpod.md) | 两枚芯片同时一次写入 | 一整层货架、一批线轴 |
| **桌面，一台读卡器** | 无法一次写完——问题正是这样产生的 | — |

手机上的操作步骤，包括“你先扫描的那枚芯片就是应用预期的 1/2”这一规则，见
[你的第一卷智能线轴](../tutorials/first-smart-spool.md)。

只有一台读卡器的情况，正是 [TigerPOD](../products/tigerpod.md) 设有两台相向而置的读卡器的原因：一次写入、一个时间戳、一对芯片。

## 值相同，却仍是两个条目

这种情况更少见，值得上报。Twin Tag ID 是必要条件，但不是充分条件——两枚芯片还必须逐字段地描述同一卷线轴：品牌、材料、三种颜色、两种外观。接下来请比较这些。

如果每个字段都匹配，而你的库存仍然把线轴拆成两个，那就是一个 bug，而不是写入错误。请在 [Discord](https://discord.gg/3Qv5TSqnJH) 上说明，并附上两枚芯片的读取结果。
